# Contributing to MicroSysAdmin

MicroSysAdmin currently uses a private, maintainer-controlled contribution workflow.

## Development setup

1. Use PHP 8.2 or newer and Composer 2.
2. Copy `config/config.sample.php` to the ignored `config/config.php` only through the installer.
3. Keep MicroSysAdmin on localhost, a private network, or a VPN.
4. Never use production credentials or customer data in tests.

## Required checks

```bash
./microsysadmin-git audit
./microsysadmin-git prepare
/opt/lampp/bin/php tests/run.php
./tests/isolated-install.sh
```

Commits should be focused and use an imperative subject. Pull requests must explain security impact, migration behavior, test evidence, and rollback behavior where relevant. Do not bypass a failing repository, secret, entitlement, demo-isolation, or update-verification check.

## Generated and local files

Do not commit `vendor/`, `dist/`, active configuration, runtime storage, logs, backups, dumps, machine credentials, or terminal state. Release packages are generated by `build-release.sh` from the documented allowlist.
